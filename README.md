# llm-spec-blind-spots

[![check](https://github.com/sproshchaev/llm-spec-blind-spots/actions/workflows/check.yml/badge.svg)](https://github.com/sproshchaev/llm-spec-blind-spots/actions/workflows/check.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Данные эксперимента к статье на Хабре
«[Нейросеть написала спецификацию интеграции за минуту. Каких вопросов она не задала](https://habr.com/ru/companies/otus/articles/1088892/)».

Двум моделям дали одно и то же расплывчатое ТЗ: интеграция интернет-магазина с WMS
логистического партнёра. Дальше смотрели не на качество текста, а на то, какие решения
модель приняла сама, вместо того чтобы спросить заказчика или партнёра.

## Быстрый старт

Нужен только `python3`, сторонние пакеты не используются. Живая модель не нужна:
все ответы уже записаны в `runs/`.

```bash
git clone https://github.com/sproshchaev/llm-spec-blind-spots.git
cd llm-spec-blind-spots
./run.sh
```

`run.sh` делает две проверки, у каждой код выхода 1 при ошибке:

- `verify_quotes.py` — каждая цитата из оценок дословно есть в ответе модели;
- `check_summary.py` — сводная таблица в `summary.md` пересчитывается из оценок и совпадает с ними.

## Как ставили эксперимент

- **Задача:** `prompts/A_spec.txt` — сразу написать спецификацию; `prompts/B_questions_first.txt` —
  сначала перечислить вопросы заказчику и партнёру, затем написать спецификацию.
- **Модели:** ChatGPT (бесплатный тариф, временный чат, модель по умолчанию) и Claude
  (claude.ai, режим инкогнито, Opus 5.5 High). По три прогона на каждый промпт, всего 12, 18.10.2026.
- **Критерии:** 14 вопросов к интеграции в `checklist.md`, записаны до первого прогона.
- **Шкала:** по каждому пункту «спросила» (вопрос или решение с явной пометкой «согласовать»),
  «решила молча» (решение без пометки) или «пропустила». К каждой оценке приложена дословная цитата.

## Результат

Формат клетки: спросила / решила молча / пропустила, по трём прогонам. Здесь пункты,
где модели разошлись; полная таблица по 14 пунктам — в `summary.md`.

| Пункт | ChatGPT A | ChatGPT B | Claude A | Claude B |
|---|---|---|---|---|
| Когда заказ уходит на склад | 1 / 2 / 0 | 3 / 0 / 0 | 3 / 0 / 0 | 3 / 0 / 0 |
| WMS недоступна | 1 / 2 / 0 | 3 / 0 / 0 | 0 / 3 / 0 | 2 / 1 / 0 |
| Дубли, идемпотентность | 0 / 3 / 0 | 3 / 0 / 0 | 3 / 0 / 0 | 3 / 0 / 0 |
| Порядок событий | 0 / 3 / 0 | 3 / 0 / 0 | 1 / 2 / 0 | 2 / 1 / 0 |
| Изменение контракта | 1 / 1 / 1 | 3 / 0 / 0 | 0 / 1 / 2 | 1 / 0 / 2 |
| Владелец ошибок | 0 / 3 / 0 | 3 / 0 / 0 | 3 / 0 / 0 | 3 / 0 / 0 |
| **Итого из 42** | **24 / 17 / 1** | **42 / 0 / 0** | **32 / 8 / 2** | **38 / 2 / 2** |
| Вопросов в среднем на прогон | 8 | 66 | 17 | 37 |

Интерфейс партнёра, источник остатка, объёмы, задержку и отмену заказа спросили все 12 прогонов.
Расхождения собрались в пунктах о надёжности обмена: на промпте A модели чаще всего решали их
сами, прямо в теле спецификации.

## Границы применимости

- Одна задача, две модели, по три прогона. Это проверка рабочего приёма, а не бенчмарк моделей.
- Оценки ставил один человек. Часть «спросила» засчитана по косвенным формулировкам; при строгом
  счёте итоги 22, 41, 28 и 34 вместо 24, 42, 32 и 38 (строгий счёт тоже проверяет `check_summary.py`).
- Вопросы у ChatGPT считались по строкам со знаком «?», у Claude — по пунктам разделов вопросов,
  поэтому эти числа сравнимы только по порядку величины. Скриптами они не пересчитываются.
- Модель бесплатного ChatGPT может смениться в любой день, повторный прогон даст другие тексты.

## Структура

```text
prompts/            два промпта эксперимента
checklist.md        14 вопросов и шкала, записаны до прогонов
runs/               12 ответов моделей как есть (служебные строки интерфейса убраны)
scores/             оценки каждого прогона по 14 пунктам с цитатами
summary.md          сводная таблица и выводы
verify_quotes.py    проверка цитат
check_summary.py    пересчёт сводной таблицы из оценок
run.sh              обе проверки одной командой
```
